## Tier 1 · 0.5.0 主题：一键接管（体验护城河）

1. **P0 · deep link 一键接管/取件**（先验证后实现）：
   - 验证 DSH web 是否支持 URL 预填 composer（`/?token=…&text=…` 或 hash 路由）——读 `_dsh-compat-test/node_modules/@deepseek-ai/dsh-client-chat` 源码定结论；
   - 可行 → 浏览器行级动作从「复制指令」升级为「接管」「接管并寄存」按钮：新开/跳转 DSH 会话并预填两行指令，取件侧同理（预填 `/inbox`）；复制按钮保留作降级路径；
   - 不可行 → 维持复制主路径（现状即 v1），在文档写明原因，不硬造。
   - **验收**：真面板点按钮到模型开始接管的全程 ≤2 次交互；或验证结论入档。
2. **P1 · 浏览区必备品选择性补齐**：cwd（项目）facet 筛选 chips（与收件箱来源筛选同款交互）；**明确不做**：成本/token 统计（ccusage 领域）、会话关系图谱（ccx 独有视角，需求未证）。验收：项目 facet 生效且与文本过滤可叠加。
3. **P1 · supersedes 接力链收件箱可视化**：defer 条件已接近达成（兼容屋已有 10 跳链卡）——组头/卡行显示「← 接力自 ho-xxx」链式标记，点击过滤同链。验收：10 跳链卡在面板可一眼看出链结构。
4. **P2 · 蒸馏保真度基准**（「跟着模型升级」的工程化）：固定源会话集（≥3 家）× 探针清单（口令/出发地/停点/涉密诱饵），脚本化跑 `/resume-*` 流程，出「探针存活率 + 四态标注率」报告——模型或 skill 文案变更后回归。验收：基准可复跑、有基线报告入库。

## Tier 2 · 战略层（0.6+，触发式启动）

1. **MCP server 出口**（`@agent-handoff/mcp-server`）：把 `handoff_push` / `handoff_inbox` / `foreign_session_read` 暴露为 MCP tools——任何 MCP 宿主（Claude Code / Codex…）都能往 `~/.handoff` 寄卡取卡，协议从「DSH 独占」升级为「多宿主参考实现」；安全闸在 MCP 层复用。**传输裁定（2026-10-08）：普通 stdio MCP 即可，不建 HTTP/WebMCP 端点**——目标宿主全是本机 CLI（stdio 全支持）；跨机由文件总线承担（HANDOFF_HOME 指同步盘，总线即网络层）；HTTP 远程端点只会重复总线职责并新增鉴权/暴露面（与面板回环-only 姿态矛盾）。核心函数传输无关，将来真有远程需求加一层 opt-in 壳即可。**WebMCP（W3C 提案 / Chrome 预览）列观察不动手**：那是「网页向浏览型 agent 注册工具」层，与 CLI agent 的 stdio MCP 互补不互斥；与我们的唯一交点在宿主层（agentic browser 操作 DSH 面板页面），插件层无可做之事——触发条件 = DSH 宿主或主流 agentic browser 实际落地 WebMCP。**启动条件**：T0-2 采用声明发出后有真实登记/问询。
2. **竞品巡检机制化**：竞品动态系列（1003/1008）固化为双周扫（GitHub API 关键词组已验证可直连），上游原生导出功能监控不变。
3. **memex transfer / mcp-agent-mail 记为相邻方向素材**：只入需求调研文档，不动代码。

## 不做清单（边界同样重要）

- 写别家会话存储（casr/cc-sessions/harness-remote 路线）——只读+蒸馏是根本分歧，永不；
- 成本统计、跨设备同步产品化——已有领域冠军，我们靠 HANDOFF_HOME 指同步盘一句话覆盖；
- 阻塞式确认面板——0.3.0 P0 已定案行内问答，不翻案；
- 关系图谱、AI 摘要另起炉灶——show 预览已覆盖摘要需求。

## 风险

- deep link 若宿主不支持，Tier 1 的体验增量主要靠 P1/P2 兜底——0.5.0 仍有可发布内容；
- harness-remote 若开放 continuation 格式为规范，T0-2 的采用叙事就是预置的对冲（开放协议先占位）；
- MCP 出口扩大维护面——用触发条件闸住，不预先投入。
