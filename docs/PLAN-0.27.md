# dsh-takeover 0.27 版本方案：可审查现场 + 顶级体验

> 2026-11-22 定稿。基线：0.26.0（754 tests 全绿，四轴一根链，23 家读取器）。
> **本版不拆子版本、不堆功能面**——一个 0.27 把体验打磨一次做到位。功能面扩张（家数、云端适配器、手机直连、--run-claims）留给后续。
> 决策依据：[真实用户需求调研](RESEARCH-0.27-USER-NEEDS.md) + [竞品功能调研](RESEARCH-0.27-COMPETITORS.md) + [顶级体验调研](RESEARCH-0.27-TOP-UX.md)。

## 〇、为什么是这一版

调研给出两个硬事实：

1. **结构化交接卡的价值被量化**：#2984 用 666 个真实会话测得「五段交接卡 95% 保真度 vs 裸重启 55%」——我们的核心抽象（一即是全·四轴一根链的一张卡）是对的。
2. **用户骂得最狠的不是功能少，而是**：卡死无逃生（#9635）、静默失败（cfanzx #3）、交接后「不知道做到哪了只看关键位置就动手做」（qqsd364）、CJK token 低估 3–4 倍（brandonzyy）。

结论：0.27 不是「再堆功能」，而是把交接从「一段被改写的话」升级成「可审查的现场」，把交互从「功能可用」打磨到「顶级手感」。

## 一、本版唯一主题

> **把交接做成可审查现场，把交互做成顶级手感。**

三根支柱，每条都有真实需求 + 顶级体验双重来源：

| 支柱 | 真实需求来源 | 顶级体验来源 |
|---|---|---|
| ① 可审查现场包 | #11108「reviewable artifact」、qqsd364「不知道做到哪了」、95% vs 55% | Claude Code Plan Mode / compact-relay 预览-确认 |
| ② 不打断 + 可诊断 | #9635「卡死无逃生」、cfanzx #3「静默失败」、CJK 低估 4 倍 | Session Watcher 灯色报决策 |
| ③ 键盘流 + 一致性 | #12365「人肉传话筒」、Pendo 80% 功能没人用 | Linear / Raycast 命令面板即前门 |

## 二、支柱①：可审查现场包（P0）

### 1. 交接预览-确认
- **改什么**：`Handoff` 按钮 / `handoff` 命令生成卡后，先展示六段预览，用户可编辑再寄存（#2984 的 100% 保真关键就是「先预览」）。
- **挂点**：交接动作 + `POST /dsh-takeover/lifeboat` + `POST /send`（server.ts:1051-1127 / 742-794）。
- **验收**：预览卡六段齐全且可编辑；取消不动状态；确认才落 pending；DOM 可断言；不新增端点名（复用既有）。

### 2.「做到哪了」机器可校验锚点
- **改什么**：六段里把「做到哪 / 还差什么 / 停在哪」做成强字段——附 git HEAD/分支/dirty 文件清单/最后一条命令与输出摘要，取件侧第一屏就是它。
- **来源**：直接回应 qqsd364「交接的新文档不知道上个文档做到哪里了只看关键位置就动手做」。#13023 提出 file-SSOT（确定性写盘 + sha 可验证）。
- **验收**：锚点字段值级保真、非 LLM 改写；取件首屏 DOM 含锚点；四态证据账本口径不变。

### 3. 回读原文开关
- **改什么**：卡里仍只存指针（保持「原文不进卡」），提供 `handoff_inbox show --with-context N` 从源会话按 seq 拉有界原文，默认关、显式授权。
- **来源**：呼应 qqsd364「把会话压缩成文件格式，需要时调出查看」；yangyizhu8 的 readback 按需回溯思想。
- **验收**：默认无 context；显式授权才读且按 seq 有界；越界/读不到诚实报错。

### 4. 接力条双向跳转 + 卡是一等对象
- **改什么**：ComposerChip 浮层（client.ts:3728-3739）做「接力自 X / 已交接给 Y」互跳；HistoryBlock（1651+）/ LedgerBlock（1793-1950）链行加跳转；整卡可跳转/回查。
- **来源**：compact-relay 交接链双向跳转（父→子一键回跳、成环停、读不到标注）。
- **验收**：父子按钮在场、点后 query 置卡 id；坏链停用给理由；成环停；`state.ledger` 缺席（老宿主）零变化。

## 三、支柱②：不打断 + 可诊断（P0）

### 5. 失败原因码
- **改什么**：寄存/取件/同步每步失败给稳定 code（`NO_COMPACTABLE_RANGE` / `TOKEN_METER_UNAVAILABLE` / `PATCH_TOO_LARGE` / `SIGNATURE_MISMATCH` / `GIT_CONFLICT`…），UI 按 code 给人话文案，不再一律「暂无可交接内容」。
- **来源**：cfanzx #3「四条出口共用一句'暂无可压缩内容'……用户和作者都无法判断卡在哪一步」。
- **验收**：每失败路径返回非空 code；UI 按 code 出文案；无 code 的失败归 `UNKNOWN` 且带上下文。

### 6. CJK 特化预算显示
- **改什么**：余量预警对中文会话加保守系数并明示估算口径——避免用户看到「24%」突然 overflow。
- **来源**：brandonzyy 实测 CJK token 低估 3–4 倍，context panel 显示 24% 而实际请求在 >1,048,568 tokens 被拒。
- **验收**：basis 写明「CJK 估算口径 + 保守系数」；不宣称精确值；分级阈值 0.7/0.85 不变。

### 7. 绝不自动切会话 + dry-run 默认
- **改什么**：默认只写卡 + 提示「可以取件了」，由用户点取件；首次用 `handoff_push --dry` / `handoff_env dry` 引导「本来会写什么」零落盘。
- **来源**：dsh-auto-handoff 的教训（默认 `autoTrigger:false`、`dryRun:true`，怕自动切会话打扰用户、怕写脏数据）。
- **验收**：无自动切会话路径；dry 零落盘；日志显示将写什么。

### 8. 预警条从「报状态」升到「报决策」
- **改什么**：basis 给「继续背 vs 现在交接」对比 + 四轴分桶预览，一个颜色就能做对决策；warn 提示 / critical 救生艇梯度保持。
- **来源**：Session Watcher 灯色 + 账单溢价 + 分桶预览（把模糊焦虑压缩成「一个颜色做对决策」）。
- **验收**：basis 含触发器与依据；**禁「预计/约/耗时/token」估算词**（context #240 前车之鉴）；不引入 EOQ 账单模型。

## 四、支柱③：键盘流 + 一致性（P1）

### 9. 命令面板当「前门」
- **改什么**：Cmd/K 从「只聚焦过滤框」扩成上下文命令面板（五视图切换 / 一键接管 / 交接出去 / 导出 / 设置，每项显示快捷键），动作与按钮共用同一 handler。
- **挂点**：`onRootKeyDown`（client.ts:3121-3130）。
- **验收**：开→过滤→回车执行→Esc 关闭且焦点归还；与既有 `/`、Cmd/Ctrl+K、↑/↓ 无冲突；zh/en 同加。

### 10. 键盘语法
- **改什么**：`G I/B/H/M/?` 五视图跳转、`J/K` 移卡、`Enter` 接管，兼容现有 ↑/↓。
- **来源**：Linear / Raycast 的「一种语法承载全部」（单字母 S/A、两键 G I、? 速查）。
- **验收**：快捷键与按钮共用 handler 不分叉；菜单旁标快捷键；`?` 速查表 zh/en 全。

### 11. 常驻占用环
- **改什么**：ComposerChip 旁 28px 占用环，不开壳可见 70/85% 黄/红，点环展开工作台并落处置动作。
- **挂点**：ComposerChip（client.ts:3728-3890），复用 `contextHealthOf`（956-985）+ `GET /state?sessionId=`。
- **验收**：warn/critical 颜色肉眼可辨（DESIGN §0 验收线）；无座位/老宿主降中性不渲染；走 `--tk-*` token 禁裸色。

### 12. 概念渐进披露
- **改什么**：四态/tombstone/T8/三态裁决藏进二级「为什么这么标」，首屏只有「接过来 / 交出去 / 取件」——不删能力，只藏呈现。
- **挂点**：`HelpCard` / 设置卡 `pane('sem')`（client.ts:4160-4165）/ guide 视图 / locales.ts。
- **验收**：首屏 DOM 不含 tombstone / 三态裁决 / T8 / 四轴术语（断言）；二级解释与 README 口径一致；locales.spec.ts 过。

### 13. 操作回执统一横幅
- **改什么**：接管 / 寄存 / 救生艇 / 批量 / 签收 / 续接同一处回执、状态三色闭集。
- **挂点**：`showNotice`（client.ts:3134-3138）。
- **验收**：横幅 DOM 文本可断言；成功绿 / 失败红 / 待确认黄闭集；8s 消失策略不变。

## 五、交付纪律（防止功能蔓延）

**一条贯穿纪律：「一个好方式 + 一张卡 + 一个入口」**——新能力必须能挂到 `--tk-*` / ComposerChip / 五视图 / 预警条某个挂点，挂不进统一叙事就宁可不做。反面案例（Photoshop / Office / MySpace / Skype）全是功能堆砌失去「为什么存在」。

1. 不新增工具名（闭集 7 名，src/index.ts:53）、不新增 npm 依赖（0.26 三波惯例）。
2. 不改 `handoff: 1` 卡面协议 / 六段 / 四态账本 / 签名三态语义；新字段走 `extras` 或 state 按需展开，**无参请求响应零变化**（server.ts:545-560）。
3. 不写外部 harness 会话存储（T8 硬线，README.md:53）；GET 读守卫 / POST 同源 + 回环闸不松（server.ts:183-197, 526-532）。
4. 不新增网络监听 / 云 API / 认证面。
5. 状态色全局唯一映射、组件零裸色、中文 ≥11px、肉眼可辨验收线（DESIGN.md:19,24,37,52,89）；禁「字距级微整」冒充 UI 更新。
6. fail-open 纪律：预检 / 握手 / 体检等辅助面异常绝不拦真实接管、绝不编状态；zh/en 文案同加；每版 `npm run check` 全绿、覆盖率 ≥95%。
